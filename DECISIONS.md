# Kıpır — Decisions

## 001: Native menu utility
SwiftUI MenuBarExtra window, AppKit lifecycle, Foundation engine; macOS 14+. No dependencies, server or event taps. One controller heartbeat avoids competing timers. Tradeoff: macOS-only delivery.

## 002: Confirm active spans conservatively
Buffer input-free time until another event confirms a gap shorter than AFK. Discard on AFK, invalid data, suspension or unknown gaps. This undercounts passive reading and can delay the visible timer by the AFK threshold, but avoids granting a full threshold on every departure. Meeting Mode freezes both schedule and statistics.

## 003: Cycle and overrides
Three completed short timers precede a long timer; completing long resets cycle. Skip resets work without advancing cycle. Snooze adds configurable active work while preserving the pending break kind. Pause/meeting preserve phase and break time. Breaks do not complete offline or while suspended.

## 004: Minimal local recovery
Persist validated confirmed session state and one local-day aggregate, never raw events. Offline elapsed time is not trusted. Crash loss is bounded by periodic checkpointing. Invalid persistence returns to safe defaults. Day rollover excludes the crossing sample.

## 005: Permission and stale actions
Notification authorization is an explicit user action. Denied/failed delivery retains a visible due state. Persisted per-episode identifiers and the last attempted delivery prevent duplicate reminders across restart and stale notification actions. Pause/meeting do not create new episodes; a failed delivery is not retried during that episode. No permission prompts at launch. Login service is optional with visible error reporting.

## 006: Identity and distribution
Kıpır is the visible brand; Kipir is the module, executable and project. Bundle identifier is configurable in Config.xcconfig. No signing team is selected; distribution, IT approval and human acceptance remain separate gates.

## 007: Break progress follows its original duration
Store the original duration alongside remaining break time. Editing future break settings does not change the current countdown or progress ring, including after restart. Fractional idle accounting subtracts the entire unconfirmed tail, not a rounded tick. Regression tests cover both.

## 008: Count active use while a break is due
A due reminder stays due with the same identity, but confirmed active work and daily totals continue. Accepting the break is not required to keep statistics accurate. Snooze adds its duration from the current active total.

## 009: Vector exercise guide with one timing authority
Native Canvas and TimelineView provide offline scalable movement without assets/dependencies. Visual animation has no scheduling authority. The scheduler feeds only accepted break-time deltas to the sequence, so AFK continues and sleep/unknown callback gaps freeze both. Navigation does not extend breaks; the final selected movement fills the remaining overall budget. Manual finish/last skip receives no completion credit. Closing hides the guide and leaves the countdown running. Restart reconstructs the default chronological position rather than persisting navigation history.

## 010 — Guide inside the menu bar popover
User preference supersedes the dedicated-window design. Render BreakExerciseView in MenuBarView while the scheduler phase is onBreak; retain the shared header, meeting toggle and footer. Dismissing the popover does not change timing; reopening displays the current movement. Remove BreakWindowController and its automatic window lifecycle. Revert the dataset instruction integration and use original Kıpır instructions/artwork.

## 011 — Free Homebrew preview
Use the existing omerahat/kipir repository as a tap via its explicit Git URL, with a
root Casks/kipir.rb and universal Release ZIP on GitHub Releases. No second tap
repository, DMG tooling, third-party dependency or automatic updater is needed.
Scripts/package-release.sh uses ad hoc signing only through command-line overrides;
project signing identities, sandbox and bundle ID stay unchanged. This is not
Developer ID signing/notarization and cannot promise Gatekeeper acceptance or OS
notification/login behavior. Never remove quarantine automatically. Pin the exact
archive SHA-256; never overwrite an existing versioned release. Publishing is a
separate authorized action. Uninstall preserves local data and has no zap hook.

## 012 — Local interface language
Use a separate validated `language` UserDefaults preference (`tr` / `en`, default/fallback `tr`) and the existing L helper with an explicit language bundle. Do not change the scheduler Settings payload or migrate session/statistics. Controller revision and SwiftUI locale refresh existing views immediately. Re-register notification categories without resending an existing due episode. Delivered notification bodies and OS error details are not retroactively translated. No new permission, dependency or network access.

## 013 — Native exercise illustrations
Use native SwiftUI Canvas with original programmatic artwork and a four-second loop; no external runtime, assets, permissions or network. Separate drawing from the popover, keep a monotonic visual-only clock, and retain the existing scheduler as the sole timing authority. The wrist close-up mirrors after halfway. Original poses are implementation evidence, not exercise or medical validation; human review remains required.

## 014 — Exercise visual QA
Inspect deterministic samples rendered from production Canvas code in both appearances. The walking illustration now uses a side-view in-place step with a fixed supporting foot; the supported calf raise keeps its hand on the support. The samples do not replace live playback or human movement review. No third-party runtime or asset is introduced.

## 015 — Five lightweight quality-of-life additions
Reuse the existing heartbeat, settings transaction, checkpoint keys and native UI. Presets are derived from all six timing values, not separately stored. The menu formatter is a pure presentation helper; AFK and overrides do not advance the displayed work countdown.

Use a native-delivery seam inside the existing NotificationManager to verify test-request construction and isolation without OS delivery. Test UI invalidation does not synchronize real reminders; the normal heartbeat continues doing so. Test identifiers cannot parse as a real reminder UUID and have no break category/actions. Accepted requests are described as submitted only.

Persist meeting expiration as optional Date and use explicit idempotent setters. Do not credit the expiration-crossing sample; retaining at most one second less work is safer than crediting frozen time. Missing deadlines mean old indefinite mode; malformed deadlines clear only the override. Expired/nonfinite/>60-minute future deadlines cancel timed mode, preserving the session. Absolute clock adjustments affect expiration as documented in ARCHITECTURE; local timezone/DST labels do not.

Completion feedback uses a nonpersistent single-consumption natural event. Capture the sound preference when completing and recheck it when consuming, so enabling later cannot replay an old disabled completion. Manual cancellation/override transitions suppress pending feedback. Use quiet native Tink rather than add an audio asset or library. Audio quality/volume and mute need human device review.

## 016 — Separate notification acceptance from desktop presentation
Preserve real reminder episodes and the one-attempt policy while reading authorization, alerts/style, Notification Center and sound as separate capabilities. Provisional permits quiet submission but never qualifies as a desktop banner. Foreground requests banner+list, with sound only when the request carries sound. System settings and Focus remain authoritative; do not add overlays, critical alerts or modify preferences. Open settings through NSWorkspace, treating pane URLs as best effort with an application/manual fallback. Visible UI is not inferred from an accepted request.

## 017 — 0.2 roadmap contracts and file ownership
Parallel work is isolated by file, not by sprint. A serial contracts commit moved exercise types to `Core/Exercises.swift`, `BreakExerciseView` to `UI/Exercises/BreakExerciseView.swift`, pre-registered every new source/test file in `Kipir.xcodeproj` and added all new persisted fields with lenient decoding (`(try? decodeIfPresent) ?? default`), so a malformed or missing 0.2 key never discards 0.1.x preferences. New Settings keys: `naturalBreak` (0/300/600/900 s, default 600), `workingHours` (disabled by default), `exerciseFocus` (`all`/`neckShoulders`/`back`/`hands`), `menuBarStyle` (`timer`/`icon`). New Checkpoint keys: `exerciseRotation`, `breakFocus`. New status `offHours`. Each workstream owns distinct files, a distinct test file and a delimited section of each Localizable.strings.

## 018 — Conservative natural break
Problem: after a genuine absence the old interval stayed and a reminder could fire minutes after returning. Rule: the scheduler accrues *verified away time* only across consecutive valid heartbeat deltas (0 < Δ ≤ 10 s on the monotonic clock) during which no input occurred, in Working or Due phase, while not paused, in a meeting or off hours. Locked screen, display sleep and an inactive session (fast user switching) keep accruing because the heartbeat keeps running and the user cannot be providing input; system sleep cannot accrue because monotonic uptime stops. Any invalid/unknown gap or restart taints the chain until new input; offline time is never trusted. When the verified away span reaches the threshold, the work interval resets (active work 0, target restored, snooze and Due cleared, which withdraws the reminder) without touching `today.breaks` or the short/long cycle. A one-shot ephemeral notice fires on the next input only if there was active work to reset. Default threshold 10 minutes (options Off/5/10/15); the effective threshold is always strictly greater than the AFK threshold. 3 minutes was rejected: brief reading/thinking pauses would reset work. 15 minutes misses many short coffee breaks; 10 minutes balances false resets (long passive video/reading without input) against redundant reminders. A false reset only delays a reminder; it never awards a completed break.

## 019 — Working hours
Optional local window (weekdays, start, end minutes; end < start crosses midnight, attributed to the start day). Evaluated each tick from wall-clock date with an injected Calendar (autoupdating in the app), so time-zone and DST changes are interpreted in local time. Outside the window: no work credit, no Due transition, no reminder and no natural-break accrual; phase/interval are preserved. A break the user already started finishes normally. Entering or leaving the window rebaselines and discards the crossing sample, like meeting expiration. Manual pause and meeting remain independent overrides.

## 020 — Deterministic exercise rotation
A persisted rotation index increments when a break starts; the catalog builds the sequence from (long, duration, focus, rotation) deterministically, and the focus captured at break start is persisted, so restarts and re-renders never reshuffle an active break. No randomness. A focus with too few movements is filled from the general catalog.

## 021 — Developer ID and notarization workflow
Public trust requires a separate maintainer-run path, Scripts/release-developer-id.sh, beside the free ad hoc preview. It needs KIPIR_DEVELOPER_ID (a "Developer ID Application" identity) and KIPIR_NOTARY_PROFILE (a notarytool keychain profile the maintainer creates with `xcrun notarytool store-credentials`); when either is missing, or the identity is absent from `security find-identity -v -p codesigning`, it prints BLOCKED and exits before building. The identity is passed only as xcodebuild command-line overrides (manual style, `--timestamp`); project signing settings, Config.xcconfig, sandbox and bundle ID are unchanged, and Release already enables the hardened runtime. The script verifies signature, identity, runtime flag, timestamp, absence of get-task-allow and both architectures. Upload to Apple, stapling and the Gatekeeper `spctl` assessment run only with the explicit `--notarize` flag and the maintainer's authorization; without it the output is a clearly named `-unnotarized.zip` that is not distributed. Versioned artifacts are never overwritten. Scripts/package-release.sh now writes the generated cask to dist/kipir.rb and replaces the tracked Casks/kipir.rb only when WRITE_CASK=1, because the cask embeds the SHA-256 of a not-yet-published archive. A notarized release lets the cask drop its Gatekeeper caveat. Quarantine removal and Gatekeeper weakening remain forbidden. Unit/guard tests with stubbed tools do not prove real signing, notarization acceptance or Gatekeeper behavior; those stay pending until run by the maintainer.

## 022 — Notification effective state and onboarding
Presentation derives `NotificationEffectiveState` (off, needsPermission, denied, limited, active) from the stored preference plus OS capabilities; the preference is never rewritten and `active` requires full authorization with desktop alerts. Each state offers at most one primary action: request permission (undecided) or open System Settings (denied, limited). Requests and opening happen only from user clicks. Authorization detail, test notification and manual guidance sit in a collapsed Diagnostics group. First run is a two-step welcome in the popover; skipping or finishing never requests permission.

## 023 — Presentation: menu bar style, status notes, durations, notices
`menuBarStyle` is `timer` or `icon`; both share one tooltip and VoiceOver summary, so state is never icon-only information. Every non-working status has a one-line localized note. Break lengths are picked from presets (short 30 s, 1, 2, 3, 5 min; long 3, 5, 10, 15 min) while storage stays in seconds; a stored non-preset appears as a disabled Custom row and is not rewritten until chosen. A `TransientNotice` (completion or natural break, 6 s) is non-persistent, expires from the controller heartbeat's monotonic time (no timer), and a completion outranks a natural break in one publish. One consumption of the completion event feeds both the optional sound and the notice; skips and manual finishes yield neither.

## 024 — Exercise catalog and rotation rule specifics
Eleven movements in four rotating areas (neck and shoulders: shoulders, neckTilt, shrug; back: chest, upperBack, twist; hands: wrists, fingers; legs: calves, march) plus `walk`. Movements last about 30 s; the count is round(non-walk time / 30), at least 1. Long breaks give 60% of the time to a closing `walk`, which is always last and never rotates. The persisted rotation index drives the choice, and rotation 0 behaves like 1. With focus all, picks go round-robin across areas starting at an area that advances with the rotation. A focus area is used first, starting at a rotating offset, and any shortfall is filled from the other areas (focus fallback; hands has only two movements). No movement repeats within a break. Durations are positive and sum to the break length, the last absorbing the remainder. The visual loop is fitted to each movement's duration (even number of cycles) so the wrist hand switch lands on a boundary. Poses are original illustrations; human review is still required for every movement.

## 025 — Review fixes
Corrections from the independent review of the 0.2 integration. Decisions 018, 019, 022 and 023 are otherwise unchanged.

- Working hours (amends 019). Entering the window is a new working period and starts a fresh interval. A genuine out-to-in transition (observed on the clock, or a restored checkpoint that was saved off hours and now lies inside the window) while Working or Due, with active work, a Due episode or a snooze, calls `resetInterval()`: active work 0, target restored, snooze and Due cleared. `today.breaks`, `today.activeSeconds` and the short/long cycle are untouched, and no natural-break notice is raised. Previously a Friday-evening Due episode survived off hours and returned silently on Monday. Off hours still suppress the reminder and credit (`reminderID` is nil), and a running break is never interrupted. Edits made in Settings (including toggling `enabled`) never restart the interval; only the clock does. The checkpoint gains a leniently decoded `wasOffHours` flag, kept equal to "last observed wall date was outside the window", so a relaunch inside the window can tell that the checkpoint predates it.
- Away accrual (amends 018). While `suspended` (screen locked, display asleep, inactive session) any finite positive monotonic delta counts as verified away time, because input is impossible and system sleep stops uptime; a coalesced heartbeat longer than 10 s no longer breaks the chain. Work credit and break countdown keep the 0 < delta <= 10 s rule, and an unsuspended gap over 10 s still taints. Backward or non-finite clocks still taint.
- Transient notices (amends 023). A notice stays pending for up to 15 minutes until the popover actually displays the row (`AppController.noticeDisplayed()` from the row's `onAppear`), then lives 6 s, expiring from the existing heartbeat. A newer event replaces an older one.
- Persistence. The checkpoint is saved at once when active work drops, the Due identity changes or the off-hours flag changes, which covers natural and window-entry resets. A malformed `exerciseRotation` is clamped to 0...1_000_000 and no longer invalidates the checkpoint.
- Effective natural-break threshold. `Settings.effectiveNaturalBreak` (max of the selection and AFK + 60 s; 0 when off) is the single rule shared by the scheduler and Settings, which states it when it exceeds the selection.
- Onboarding (corrects 022). Decision 022 says "skipping or finishing never requests permission"; the first-run welcome has no skip control, only Next and finishing. Finishing never requests permission. Setting `onboarded` now publishes immediately, and the welcome resumes at the notification step once the system permission is determined.
- Copy: the natural-break notice and the suspended note now say plainly that the work timer restarted or that work time is not counted. Unused keys `welcome.title`, `welcome.body` and `timer.break` were removed.

## 026 — Illustrated exercise poses replace the Canvas figure
The programmatic Canvas figure was judged visually poor by the maintainer. Replace it with two raster key poses per movement generated with ChatGPT image generation in one conversation (same character, flat style, white background, two panels per image), at the maintainer's request. `Scripts/PrepareExerciseImages.swift` reproducibly splits each two-panel source at its emptiest central column, crops both poses with one shared rectangle so the figure does not jump, and writes 360 px @2x PNGs (about 1.7 MB in total) into the asset catalog. Playback holds each pose and crossfades briefly (`exercisePoseBlend`, tested); the visual clock, Reduce Motion behavior and scheduler authority are unchanged. This supersedes the "programmatic artwork, no assets" parts of 009/013/014/024. Images are generated, not hand-authored; pose accuracy still requires human review.

## 027 — Homebrew with ad hoc signing is the distribution path
The maintainer has no Apple Developer ID and distributes through the repository's Homebrew cask. Releases use `WRITE_CASK=1 bash Scripts/package-release.sh` (universal, ad hoc signed, immutable versioned ZIP, pinned SHA-256), a GitHub release with the ZIP and checksum, then the updated cask on `main`. Developer ID/notarization is not planned; `Scripts/release-developer-id.sh` remains an optional, guarded path and is no longer tracked as a blocker. The cask caveat keeps the Gatekeeper "Open Anyway" guidance; never instruct users to remove quarantine.

## 028 — Meeting mode only silences interruptions (supersedes the meeting parts of 0.1/018/025)
Meeting mode is orthogonal to timing. Work credit, the countdown, statistics, break playback, idle and natural-break rules and every phase transition run exactly as without it. While it is on: no reminder notification (`reminderID` stays nil), no break-completion sound (the completion event is still consumed and the break is still credited), and the current Due episode's reminder is recorded as attempted (`NotificationPolicy.markingMeetingSuppressed`), so ending the meeting never replays it; later episodes notify normally. A reminder already delivered is withdrawn when the meeting starts. Start break and snooze stay available; a running break shows as `onBreak` (it outranks `meeting`). The user-initiated test notification is deliberately not silenced. Toggling or expiring a meeting no longer rebaselines, and a repeated sample at the same instant no longer discards unconfirmed credit. Consequence: a long meeting without input can now restart the interval like any other away span.

## 029 — Interface language: System Default
`language` is "system" (missing key), "tr" or "en". System Default follows `Locale.preferredLanguages` (including the per-app language in System Settings; `CFBundleLocalizations` now lists tr and en). An explicit choice overrides it. If no preferred language is supported, the fallback is English, as the more widely readable choice for non-Turkish users; Turkish remains the development region. Existing users who explicitly chose a language keep it; users who never chose one now follow macOS.

## 030 — AppKit status item, popover and Settings window
`MenuBarExtra` was replaced by `StatusBarController` (`NSStatusItem` + `NSPopover` + an owned Settings `NSWindow`), because `MenuBarExtra` provides no programmatic presentation (needed to open from a notification), no stable label geometry and no appearance control for its window. The label is one constant-size template image: an icon slot plus a text slot measured over every label in both languages. The text is always remaining minutes, or "Mola"/"Break" when due; state is shown by the icon. A notification body click and an item click share one `showPopover()`, which is idempotent and queued before installation. One `applyAppearance()` sets the popover and Settings window appearance from `Settings.appearance`. "System" resolves the system appearance explicitly, since a popover otherwise inherits the menu bar's. The SwiftUI `Settings` scene is empty; its ⌘, command opens the owned window. The countdown ring draws `remainingFraction` (full at start, receding counterclockwise from 12 o'clock to empty at zero; a snooze refills it).

## 031 — Stable vertical layout in the work-countdown popover
Root cause: `MenuBarView` rendered a one-line state note (`ui.status.note.<status>`) above the countdown ring for every non-working status, so pause, resume and meeting toggles inserted or removed a multi-line caption and pushed the ring and action row down; separately the Pause/Resume button was content-sized, so its width and centre changed with the localized label. Fix: on the countdown screen the note is shown below the primary controls via `PopoverStatusNote` (pause shows none; the badge and Resume button already say it), and the action-row buttons use `frame(maxWidth: .infinity)` labels so Pause/Resume and the break button have constant frames. The popover is top-anchored under the menu bar, so content added below cannot move the controls. The break/exercise screen is unchanged. No timer or meeting-suppression semantics changed. `ui.status.note.paused` stays because the break screen still uses it.
- Follow-up: the meeting explanation (`ui.status.note.meeting`) now renders inside the meeting section, below the toggle row and above the remaining-time/"End meeting" row, instead of above the statistics card. Everything above and including the toggle is structurally identical with meeting on or off.

## 032 — Smooth ring between heartbeats
Cause of the "chunky" ring: the scheduler advances only on the 1 s controller heartbeat (timer tolerance 0.2 s), and the ring drew `remainingFraction` directly, so it stepped once per tick (clearly visible on short countdowns). `CountdownRing` now keeps a displayed value and animates a small forward decrease linearly over 1 s. This is rendering only: no second timer, the countdown value and semantics are untouched. Increases (snooze, reset), large jumps and Reduce Motion update instantly. The drawn arc lags the scheduler by at most one heartbeat. The digits still change once per second.
